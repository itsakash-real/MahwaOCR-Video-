## Video — the current system (Genius Knight, 2026-10-26 Phase B)

- The Genius Knight movie style is the current long-form movie mode on
  `main` (commit `ea90739`, `manhwa_ocr/video/framepipe.py`, spec
  `docs/GENIUS_MOVIE_STYLE.md`, CLI
  `python -m manhwa_ocr video movie --shots shots.json --audio audio.wav --out out.mp4 --cuts-dir cuts/... --total <seconds>`).
- Lock inputs first. Script covers all important panels, in story order,
  join-safe, no intro/outro. Audio is frozen before video.
- Approved cuts only: 900px wide, vertical only, originals in `cuts_orig/`.
  Skip ONLY blank, white-only, or bubble-only panels. Never silently
  substitute pipeline panels, re-detected panels, or panelfit crops for
  approved cuts. If approved cuts cannot be used, STOP and tell the user.
- Mapping is sentence-by-sentence, story order, with panel + subject note
  + window. Windows are 900x506 zoom / 900x560 slide. The subject must
  stay whole through the FULL motion path.
- One shot per sentence, sentence-synced (NOT fixed 2s/image).
  Frames = round(duration x 30). Total frames = round(total seconds x 30).
- Motion runs (same source + window = one run / invisible hold), cycling
  zoom_in -> slide_up -> slide_down -> zoom_out, very slow.
  Zoom 1.00 <-> 1.05, centre crop. Slide 115px on a 1920x1195 base.
  Frame 0 is fully settled. Hard cuts only.
- Render: PIL every frame once -> rawvideo -> ffmpeg libx264, veryfast,
  crf 18, yuv420p, 1920x1080, 30fps, AAC 192k, NO `-shortest`, LANCZOS resize.
- Gates, in order, never `--force`: duration (1920x1080 / 30fps /
  duration = audio / frames = expected); sync (never forced); full-bleed
  (mid-frame of every shot, shape exactly 1080x1920, near-white measured,
  FLAG > 30%); transition dominance (10fps 320x180 diffs, boundary step
  > 2.5x neighbour max, except EXEMPT-HOLD same-run and EXEMPT-REFRAME
  same-source); first/mid/last visibility of EVERY shot.
- Separate re-verification: first/mid/last of every shot again. Fixes are
  window moves / re-pairs / re-cuts only, audio untouched. Fixed shots
  and neighbours are re-checked. Repeat to 0 FAILs. Residues are listed
  openly, never hidden behind a PASS.
- Combined movie: stream-copy concat only, absolute paths, no re-encode,
  no intro, no breaks, no fades. Verify duration/frames = exact sum,
  hard-cut joins. Fresh filenames for every delivery. Never deliver a
  partial set when the user ordered everything together.

## Placement law (all long-form, unless the Genius full-bleed mode is ordered)

- Panels big, CENTRED, scaled until they touch the top and bottom walls
  of the 1920x1080 frame. Never floating. Never scrolled / traversed /
  drifted as the presentation. Zero white bands, gaps, or letterbox space,
  verified on rendered frames.
- Tall / 9:16 rule (user, 2026-10-27): if a sentence's whole context is
  tall and cannot be shown in 16:9 even with sliding, (1) note/log it,
  (2) still render it in 16:9 as the main version, (3) ALSO render an
  alternate in 3:4 or 9:16 (blur background, best fit), (4) share BOTH
  2-6s clips for a user decision, (5) never halt the whole render for
  one such part. Priority: face first, then main background action,
  text/bubble secondary.

## Quality — hard, overrides speed

- 1920x1080, 30fps, crf 18, LANCZOS, full-bleed, no pillars, no blur
  backdrops, no white bands.
- Bitrate at or above the Genius range 1,278-1,419 kbps. Under ~1 Mbps is
  FAIL even if the container says 1080p. A part at ~1.1 Mbps (Chapter 1
  parts 2/3, 2026-10-27) is soft and must be re-rendered at a lower crf
  (crf 14/16 were used for the Chapter 1 re-renders).
- Source panels are 900px. True detail above 1080p does not exist. Do
  NOT fake 4K by upscaling to 3840x2160.
- Quality beats any time target. If they conflict, report a delay, do
  not ship a soft video.

## Audio — locked format (user order, 2026-10-27)

- Deepgram aura-2-odysseus-en, native 1.3 (NOT atempo), one API POST per
  paragraph, 0.25s gaps between paragraphs, line breaks -> single spaces
  only, do NOT collapse `...`.
- The 1.0x + ffmpeg atempo=1.3 method (C) is FORBIDDEN. Per-sentence
  posting (A) is fallback ONLY if paragraph sync recovery fails on a
  one-chapter test.
- Mandatory before video use: whisper completeness check per paragraph,
  sentence-sync recovery from whisper word timings, WPM check (>= 90% of
  paragraphs within +/-30% of median).
- Why: single-post calls can silently truncate (proven twice on Chapter 1).
  A truncated paragraph is re-voiced ONLY for that paragraph, never the
  whole script. Script fixes are also paragraph-only, never whole-script.
- Voice pacing SOP: sentences 10-16 words, one idea, `...` max 1 per
  paragraph, `!` max 1 per paragraph, no ALL-CAPS, numbers in words,
  no brackets / [Beat N] / meta text.
- Measured full-script test (1,439 words, 29 paragraphs): A 432.31s,
  B 408.20s (winner), C 442.92s (worst). These numbers are for that
  script only, not universal constants.
- Other voices, kept separate: Solo long-form odysseus @ 1.35, gap 0.11.

## Transcription

- AsuraScans chapter pages: page JSON embeds the first entry as a wide
  credits banner (1532x1024) followed by 900px-wide strips. Extract with
  a strict `[a-f0-9]{6}\.webp` pattern; treat entry #1 as the credits page.
- Fan-out: split a chapter into 4 tile ranges (001-045, 046-091, 092-136,
  137-end), one worker per range writing part files, then a coordinator
  merges with renumbered scenes + deduped boundaries. A single agent
  reading ~180 tiles blows its context limit and dies mid-chapter.
- Gemini verification: strictly sequential, one key at a time, rotate
  ONLY on 429, exponential backoff + circuit breaker, never parallel
  blast (quota is per project, not per key). Model: gemini-3.5-flash-lite.
- Panel descriptions in `panels.json` can be flat wrong. Judge the single
  panel file before re-pairing. Fix ONLY wrong sentences in pairing;
  chosen panel must depict the sentence's subject; avoid text/bubble-only,
  blank, or credit panels; keep panel count per sentence unless clearly
  wrong.
